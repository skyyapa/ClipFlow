# ClipFlow 技术方案

## 1. 推荐技术栈

- **桌面端**：C# + WPF
- **存储**：SQLite + FTS5 全文索引
- **图片**：应用数据目录中的内容寻址文件存储
- **系统集成**：Windows Clipboard API、全局快捷键、托盘与窗口焦点 API
- **发布**：单实例桌面应用，可选择便携版或安装版

选择 WPF 的原因是 Windows 剪贴板、全局快捷键、托盘、透明浮窗和焦点控制都需要成熟稳定的系统集成。ClipFlow 的竞争力来自响应速度和可靠性，不来自跨平台 UI。

## 2. 模块结构

```text
ClipFlow.App
├─ Shell                 托盘、生命周期、单实例
├─ Clipboard             监听、读取、格式解析、去重
├─ History               记录、收藏、删除、保留策略
├─ Search                FTS 索引、过滤、排序
├─ Paste                 写回剪贴板、纯文本、焦点恢复
├─ Queue                 连续粘贴状态机
├─ Transform             文本清洗、分隔符与 TSV 转换
├─ Storage               SQLite、图片文件、迁移与清理
├─ Privacy               暂停、应用排除、敏感项策略
└─ UI                    快速浮窗、片段库、设置
```

## 3. 数据模型

### ClipboardItem

- `Id`
- `ContentType`
- `PlainText`
- `HtmlContent`
- `BinaryPath`
- `ContentHash`
- `SourceApp`
- `CreatedAt`
- `LastUsedAt`
- `UseCount`
- `IsPinned`
- `IsFavorite`
- `Title`
- `SizeBytes`

文件条目另存文件路径列表；标签使用独立关联表。相同内容通过哈希合并，同时更新最后复制时间和复制次数。

## 4. 剪贴板监听

- 使用系统剪贴板格式监听，而不是高频轮询
- 读取失败时进行短暂、有上限的重试
- 写回剪贴板时设置内部标记，避免把自己的粘贴再次记录为新条目
- 大图片在后台生成缩略图，不阻塞剪贴板线程
- 数据库写入进入单独队列，避免影响复制动作

## 5. 搜索

- 正文、标题、标签和文件名进入全文索引
- 查询输入使用短防抖
- 结果列表采用虚拟化
- 空查询只读取最近记录，不扫描全表
- 收藏和使用频率只影响排序，不改变关键词匹配结果

## 6. 粘贴流程

1. 记录呼出前的前台窗口句柄。
2. 用户选择条目。
3. 将目标格式写入系统剪贴板。
4. 隐藏 ClipFlow。
5. 恢复原窗口焦点。
6. 发送粘贴操作。
7. 必要时恢复用户此前的剪贴板内容。

自动发送按键可能受到权限级别限制；普通权限应用不能可靠控制管理员权限窗口。因此需要明确提示，并提供“只复制、不自动粘贴”的降级路径。

## 7. 性能约束

- UI 线程不进行数据库写入、图片编码或全文索引更新
- 搜索请求可取消，旧请求不能覆盖新结果
- 图片按需解码，并限制缩略图内存缓存
- 历史清理分批执行
- 所有系统监听在退出时正确注销

## 8. 测试重点

- 100%、125%、150%、200% 缩放
- 多显示器及不同缩放组合
- Office、WPS、微信、浏览器、IDE 和远程桌面
- 大图片、大段 HTML、大量文件路径
- 剪贴板被其他应用占用
- 应用崩溃、系统休眠、资源管理器重启
- 管理员窗口和安全桌面降级行为
